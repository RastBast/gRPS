# MISTAKES

Журнал повторяющихся ошибок. Цель — не повторять.
Формат записи:

```
## YYYY-MM-DD — короткое название
- Что сделал:
- Как сломалось (ошибка, лог):
- Почему (корень):
- Как чинить / правило:
```

## Список

### 2026-09-16 — знания остались в незамерженной ветке (PR #1)
- Что сделал: PR #1 с файлами памяти (`README/PROGRESS/TECH_DEBT/MISTAKES`) был закрыт **без мержа**. Файлы остались только в ветке `arena/01a0a07d-grps`.
- Как сломалось: следующий чат стартовал без памяти о проекте и целях. Проверка: `git ls-files` в `main` их не видел, `git log --all -- PROGRESS.md` показывал их только в той ветке.
- Почему (корень): «сделал PR» ≠ «сделал merge» ≠ «сделал `git pull` на своей машине». Три разных действия, между ними теряются данные.
- Как чинить / правило: после merge PR **всегда** `git checkout main && git pull origin main`. Если ветка чужая и файлы нужны срочно — `git checkout <ref> -- <файлы>` (кладёт и в индекс, правки перезаписывает молча!) или `git restore --source=<ref> <файлы>`.

## Косяки ментора (мои, фиксируются, чтобы не повторять)

### 2026-09-16 — формулировка «внутри error лежат два поля»
- Что было: написал, что у `error` «два поля: динамический тип и значение».
- Как сломалось: ученик прочитал так, будто у ошибки есть поля-данные, и потерял нить объяснения.
- Почему: смешал две разные вещи — встроенный интерфейс `error` (метод `Error() string`, полей нет) и устройство **значения интерфейса** в рантайме (`iface{tab, data}`).
- Правило: интерфейс объясняем через «коробку и наклейку», а не через поля. Формулировки про рантайм — только с оговоркой «это про значение интерфейса, не про сам интерфейс».

### 2026-09-16 — тема errors подана как отдельная неделя и как теория
- Что было: развернул sentinel/`%w`/`Is`/`As` целым шагом на 30+ минут без кода.
- Как сломалось: M упало до 2 («рутина, которую ИИ делает на 99%»), интерес умер.
- Почему: тема звучала как самоцель, а не как то, без чего не работает маппинг ошибок в gRPC-коды и не проходят тесты.
- Правило: тему ошибок даём только вплотную к реальному хендлеру/тесту. Одна тема — один видимый результат.
